## 01. Identitas & Ringkasan Tahap

Tahap 04 berfokus pada pembangunan modul **Manajemen Profil Pelanggan & Alur Pengajuan Verifikasi Identitas Resmi (*Know Your Customer / KYC*)**. Verifikasi identitas merupakan pilar keamanan fundamental platform CamHub guna mencegah penipuan, penggelapan unit kamera sewa bernilai tinggi, dan memenuhi standar transaksi escrow. Implementasi mencakup pengelolaan biodata alamat pelanggan, formulir pengajuan KYC multi-step sesuai prototype visual, pengunggahan dokumen aman (Foto KTP dan Swafoto/Selfie memegang KTP), pemantauan status verifikasi (*Pending, Approved, Rejected*), serta pencatatan audit log keamanan.

---

## 02. Ruang Lingkup & Batasan Pengerjaan

### 02.01 Termasuk dalam Pengerjaan (In-Scope)
- **Persiapan Branch:** Membuat branch kerja `tahap/04-profil-pelanggan-kyc` yang dicabangkan langsung dari branch `develop` terbaru.
- **Manajemen Profil Pelanggan:**
  - Halaman detail biodata pelanggan: Nama Lengkap, Username, Email, No. HP, Alamat Domisili, Kota, dan Lencana Status KYC.
  - Formulir pembaruan profil (*Edit Profile*): Memperbarui alamat, kota, dan kontak dengan validasi server-side.
- **Alur Verifikasi KYC (Sesuai Mockup 100%):**
  - Tampilan formulir pengajuan multi-langkah (*Multi-Step KYC Form*):
    - **Langkah 1 (Data Diri KTP):** Nama lengkap sesuai KTP, Nomor Induk Kependudukan (16 digit NIK), Tanggal Lahir, Jenis Kelamin (Laki-laki / Perempuan).
    - **Langkah 2 (Unggah Dokumen):** Upload Foto KTP asli & Swafoto memegang KTP dengan panduan visual pengambilan foto yang benar.
    - **Langkah 3 (Pernyataan & Konfirmasi):** Pernyataan keabsahan data dan tombol submit pengajuan.
- **Sistem Upload Dokumen Aman (Secure File Upload):**
  - Penyimpanan file di direktori privat/terisolasi `public/uploads/kyc/` atau `storage/uploads/kyc/`.
  - Validasi ketat MIME type server-side: hanya mengizinkan `image/jpeg`, `image/png`, `image/webp`.
  - Pembatasan ukuran berkas maksimal **2 MB** per file.
  - Pengacakan nama berkas menggunakan *cryptographic unique hash* (misal: `ktp_65abc123_uuid.jpg`) untuk mencegah penimpaan file (*file collision*) dan akses brute-force.
- **Pelacakan Status & Proteksi Alur:**
  - Status submission: `pending` (Menunggu Tinjauan), `approved` (Terverifikasi), `rejected` (Ditolak dengan Catatan).
  - Jika status `pending`, pengguna dilarang mengajukan ulang hingga ada keputusan.
  - Lencana status interaktif ditampilkan jelas di Dashboard Pelanggan.
- **Pengujian Mandiri (100% Automated Testing Gate):** Skrip `tests/test_kyc.php` yang menguji 10 parameter uji komprehensif.

## 03. Analisis Teknis & Pilihan Solusi (Trade-Offs)

### 03.01 Arsitektur Penyimpanan Berkas Identitas (KTP & Selfie)
- **Opsi A (Direkomendasikan): Penyimpanan Terstruktur dengan Hashing & Validasi Ekstensi Ketat**
  - *Mekanisme:* Berkas disimpan di `public/uploads/kyc/` dengan nama yang di-hash (misal: `hash_hmac('sha256', uniqid(), $key) . '.jpg'`). Validasi menggunakan `finfo_file()` atau `mime_content_type()` untuk memeriksa *magic bytes* file asli, bukan hanya mengandalkan ekstensi nama berkas.
  - *Kelebihan:* Menjamin performa cepat di Apache/Laragon, mencegah *arbitrary PHP script execution* (RCE), dan file nama aman dari karakter berbahaya.
- **Opsi B: Menyimpan Binary Gambar ke Database (BLOB)**
  - *Kekurangan:* Membebani ukuran database MySQL dan memperlambat waktu respons query.
- **Keputusan:** Mengadopsi **Opsi A**.

### 03.02 Validasi NIK KTP Indonesia
- **Opsi A (Direkomendasikan): Validasi Panjang 16 Digit Angka & Tanggal Lahir**
  - *Mekanisme:* Regex `^[0-9]{16}$` serta pengecekan tanggal lahir logis.
  - *Kelebihan:* Memastikan data NIK valid tanpa memerlukan akses ke API Disdukcapil eksternal berbayar.
- **Keputusan:** Mengadopsi **Opsi A**.
