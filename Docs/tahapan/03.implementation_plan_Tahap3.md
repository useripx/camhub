## 01. Identitas & Ringkasan Tahap

Tahap 03 berfokus pada pembangunan sistem **Autentikasi Pengguna Terintegrasi & Pengendalian Hak Akses Berbasis Peran (*Role-Based Access Control / RBAC*)** untuk 3 aktor utama platform: **Customer**, **Partner**, dan **Administrator**. Implementasi mengacu penuh pada prototype **CamHub — Login & Register.png** dengan layout *split-screen*, mendukung login fleksibel via **Username, Email, ATAU Nomor HP**, termasuk penyediaan akun instan default **admin:admin**, **user:user**, dan **mitra:mitra** untuk kemudahan pengujian browser dan presentasi tim, registrasi akun baru, proteksi password hashing BCRYPT, manajemen session aman, proteksi CSRF token, validasi form server-side, serta middleware route guard untuk memproteksi halaman aplikasi.

## 02. Ruang Lingkup & Batasan Pengerjaan

### 02.01 Termasuk dalam Pengerjaan (In-Scope)
- **Persiapan Branch:** Membuat branch kerja `tahap/03-autentikasi-pengguna` yang dicabangkan langsung dari branch `develop` terbaru.
- **Pembaruan Skema Basis Data (Kolom `username`):** Menambahkan kolom `username VARCHAR(50) NULL UNIQUE` pada tabel `users` untuk mendukung login via username langsung (`admin`, `user`, `mitra`).
- **Seeding Akun Default Siap Pakai (Permintaan Khusus Project Owner):**
  - **Akun Admin:** `admin` / `admin` (Role: `admin`)
  - **Akun Customer/User:** `user` / `user` (Role: `customer`)
  - **Akun Mitra:** `mitra` / `mitra` (Role: `partner`)
- **Antarmuka Visual (Sesuai Mockup 100%):**
  - Halaman Login ([`resources/views/auth/login.php`](../../resources/views/auth/login.php)): Layout split-screen dengan panel kiri navy gelap memuat logo CamHub, tagline besar, 3 keunggulan ber-checkmark, panel kanan formulir input bersih, serta quick-info card kredensial demo (`admin:admin`, `user:user`, `mitra:mitra`) agar penguji/dosen mudah mencoba.
  - Halaman Register ([`resources/views/auth/register.php`](../../resources/views/auth/register.php)): Formulir pendaftaran akun (Nama, Username, Email, No. HP, Password, Konfirmasi, Pilihan Peran: Customer atau Mitra).
- **Logika Autentikasi Backend:**
  - Login multi-identifier: Mendukung autentikasi menggunakan **Username, Email, ATAU Nomor HP**.
  - Verifikasi password aman menggunakan `password_verify()` terhadap hash BCRYPT pada database.
  - Pendaftaran akun baru dengan validasi keunikan username, email, dan nomor HP.
  - Pembuatan profil otomatis (`user_profiles`) saat customer mendaftar, atau inisialisasi entitas `partners` & `partner_stores` saat mitra mendaftar.
- **Manajemen Session & Keamanan:**
  - Regenerasi session ID (`session_regenerate_id(true)`) saat login sukses untuk mencegah *session fixation attack*.
  - Penyimpanan payload session: `user_id`, `username`, `role_id`, `role_name`, `full_name`, `email`.
  - Generator dan validator **CSRF Token** pada setiap form POST.
- **Pengalihan Peran Otomatis (Role-Based Redirection):**
  - Akun **Customer** diarahkan ke dashboard pelanggan (`/dashboard/pelanggan`).
  - Akun **Partner** diarahkan ke dashboard mitra (`/dashboard/mitra`).
  - Akun **Admin** diarahkan ke dashboard administrator (`/dashboard/admin`).
- **Middleware & Route Guards:**
  - `AuthMiddleware`: Memastikan request berasal dari user yang telah terotentikasi.
  - `RoleMiddleware`: Membatasi rute hanya untuk peran tertentu (mencegah customer masuk dashboard admin/mitra).
  - `GuestMiddleware`: Mencegah pengguna yang sudah login mengakses kembali halaman login/register.
- **Catatan Jejak Audit:** Mencatat setiap aktivitas login, gagal login, dan registrasi ke tabel `audit_logs`.
- **Pengujian Mandiri (100% PASS Gate):** Skrip `tests/test_auth.php` yang menguji 10 skenario lengkap (termasuk verifikasi login `admin:admin` dan `user:user`).

## 03. Analisis Teknis & Pilihan Solusi (Trade-Offs)

### 03.01 Mekanisme Login Multi-Identifier (Username / Email / No. HP)
- **Keputusan:** Kueri pencarian user menggunakan:
  ```sql
  WHERE username = :identifier OR email = :identifier OR phone = :identifier
  ```
  Ini mengizinkan user memasukkan `admin` (username), `admin@camhub.id` (email), ataupun `081111111111` (no HP), semuanya dipetakan ke akun yang tepat.
- **Kelebihan:** Sangat fleksibel, memenuhi 100% permintaan Project Owner untuk login instan `admin:admin` dan `user:user`, sekaligus tetap mematuhi desain mockup (*"Email atau No. HP"*).

### 03.02 Akun Default & Password Hashing
- Akun `admin` di-hash dengan `password_hash('admin', PASSWORD_BCRYPT)`.
- Akun `user` di-hash dengan `password_hash('user', PASSWORD_BCRYPT)`.
- Akun `mitra` di-hash dengan `password_hash('mitra', PASSWORD_BCRYPT)`.
- Semua tersimpan di basis data dalam bentuk hash aman standar industri PHP 8.x.

### 03.03 Arsitektur Middleware pada Routing Native
- Router mendukung pipeline middleware terdefinisi rapi di `routes/web.php`.
- Middleware dieksekusi berurutan sebelum controller dipanggil.
